Agentic AI Architecture

Customer Support Triage + Action Agent (Tool-Calling Workflow)

LangGraph • Tool Calling • Policy Guardrails

🎯 Use Case

User says: "My order #88421 was delivered to the wrong address. I want a replacement shipped overnight."

The agent classifies intent → retrieves order data → validates policy → executes safe actions → generates a customer-ready response.

🔷 High-Level Flow

1️⃣ Intent Classification

Structured output via LLM function-calling.

  • Intent: delivery_issue
  • Action: replacement
  • Shipping: overnight_requested
2️⃣ Fact Retrieval Tools
  • get_order_details()
  • get_tracking_status()
  • check_inventory()

Pulls verified backend data before reasoning.

3️⃣ Policy Guardrails
  • Overnight allowed?
  • Replacement eligibility?
  • Fraud check

Deterministic policy engine — not LLM guesswork.

4️⃣ Clarification Node

If needed:
“Please confirm the correct shipping address.”

Controlled conversational branching.

5️⃣ Action Tools
  • create_replacement_order()
  • upgrade_shipping()
  • open_support_ticket()
6️⃣ Response Generation

Customer-ready message summarizing:

  • What was done
  • Tracking number
  • Expected delivery

🛠 Technology Stack

Agent Orchestration
  • LangGraph (Stateful Workflow)
  • Structured Output via JSON Schema
  • Tool Calling with Pydantic Models
Security & Backend
  • Flask REST APIs
  • MySQL / SQLAlchemy
  • Keycloak OAuth2 Resource Server
⚠ Guardrail Principle

The LLM does NOT directly refund, replace, or upgrade shipping. It proposes structured actions. Deterministic backend services enforce policy before execution.

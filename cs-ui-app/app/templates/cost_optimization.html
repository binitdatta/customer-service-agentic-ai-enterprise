Cost Optimization

Cost is a design constraint. For an agentic support system, optimization spans LLM usage, API efficiency, database workload, observability volume, and identity/security controls.

CS-Triage LLM + Tool Calling FinOps
Rule of Thumb: Reduce repeated work (tokens, retries, queries, logs) before you reduce capacity. Most savings come from fewer model calls, fewer tool calls, and smaller telemetry volume.
Cost → Quality → Safety

1️⃣ Primary Cost Drivers

LLM Tokens

System prompts, conversation history, tool outputs, and retries are the biggest drivers.

Tool Calls

Each API call has infra + latency cost. Excessive fetching is common in early agent builds.

Data + DB

N+1 queries, chatty patterns, and large payloads inflate compute and storage.

Observability

Logs, metrics, traces, and security events can exceed compute spend if not governed.

2️⃣ High-ROI Quick Wins

LLM Usage Controls
  • Summarize memory before context grows (rolling conversation summaries).
  • Strict structured output (Pydantic / JSON schema) → fewer retries.
  • Two-stage reasoning: cheap classifier → expensive reasoning only when needed.
  • Cache deterministic steps: policy decisions, tool schemas, reference text.
  • Limit tool output size returned to the LLM (return only required fields).
Tool-Calling Controls
  • Batch reads: one Orders API call returns order + shipment + address snapshot.
  • Idempotency keys for replacement/ticket creation → avoid duplicate costs.
  • Retry budget: bounded retries with exponential backoff and jitter.
  • Read-through caches for common lookups (inventory availability, SLA policy).
  • Prefer server-side joins over multi-hop client orchestration.

3️⃣ Policy & Security as Cost Controls

Strong authorization reduces expensive “undo” work (refund reversals, duplicate replacements, manual escalations). 4️⃣ Observability Cost Governance

Telemetry Strategy

Treat telemetry as a metered product. Use sampling and retention tiers.

  • Logs: keep structured logs; redact PII; cap payload sizes; enforce log levels by env.
  • Metrics: low-cardinality dimensions; avoid exploding label sets (tenantId/userId).
  • Traces: head-based sampling + always-sample on errors and policy denies.
  • Security events: retain longer than traces; keep them compact and high-signal.
Retention Tiers
Signal Default Hot / Cold
Metrics 30–90 days Hot longer
Logs 14–30 days Archive sampled
Traces 3–7 days Error traces longer
Security Events 90–365 days Cold storage
(Tune to compliance and incident-response needs.)

5️⃣ Scaling and Deployment Cost Controls

Right-Sizing + Autoscaling
  • Set CPU/memory requests/limits per service (UI, Orders, Workflow).
  • Autoscale on RPS + p95 latency, not CPU alone.
  • Separate “burst” workloads (LLM-heavy) from “steady” workloads (API/DB).
Database Cost Hygiene
  • Add the right indexes for order lookup and ticket correlation.
  • Use read replicas for heavy read paths (order status checks).
  • Archive completed workflows to cheaper storage.

✅ Cost Optimization Checklist

Watch-out: The fastest way to blow budget is high-cardinality telemetry and “looping agents” (repeated tool calls + repeated prompts). Put budgets and circuit breakers in the agent runtime.

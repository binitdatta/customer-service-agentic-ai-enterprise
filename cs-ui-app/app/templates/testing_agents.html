Testing Agentic Systems

Testing an Agentic AI is fundamentally different from testing CRUD APIs. We validate reasoning, tool selection, policy enforcement, RBAC, observability, and end-to-end workflow behavior.

1️⃣ What Are We Testing?

LLM Reasoning

Intent classification, structured extraction, clarification logic, hallucination resistance.

Tool Invocation

Correct API selection, parameter validation, idempotency, safe retries.

Policy Guardrails

Prevent unauthorized replacement, refund, overnight shipping, or privilege escalation.

End-to-End Telemetry Flow

2️⃣ Testing Layers

Layer Example Tooling
Prompt / LLM Unit Test “Wrong address + overnight” → Classified correctly? LangChain Eval / JSON schema validation
Tool-Calling Test Replacement order created with correct item ID? Pytest + Mocked APIs
Policy Test Overnight shipping denied without entitlement? Rule Engine Assertions
RBAC Test Requires replacement_create role JWT Role Inspection
E2E Integration UI → API → Workflow → DB mutation verified Postman / Newman / Cypress

3️⃣ Security & Role Validation

The cs-triage realm enforces role-based controls. Critical operations such as:

  • replacement_create
  • order_write
  • ticket_write

Must be present in the JWT realm_access.roles claim before any state-changing action is executed.

4️⃣ Observability-Driven Validation

Distributed Tracing

Correlation IDs across UI, Orders API, Workflow API. Verify no missing span in decision path.

Security Events

Unauthorized action attempts must generate auditable events. Validate token expiry and audience claims.

5️⃣ Chaos & Failure Injection

  • Orders API unavailable → Agent retries safely
  • Inventory unavailable → Alternative resolution suggested
  • Workflow timeout → Ticket auto-created
  • Expired JWT → Graceful re-authentication
Key Principle: An Agent is correct only if it produces the right reasoning, selects the correct tool, respects policy, enforces RBAC, and generates observable evidence of its decision path.

Deployment Architecture

A production-ready reference deployment for the Customer Support Triage + Action Agent. This architecture emphasizes secure identity, least privilege, observability, and safe tool-calling.

cs-triage realm OIDC / JWT

1️⃣ Core Runtime Components

CS UI (Flask)

Customer-facing UI and chat surface. Performs OIDC login and routes user actions to backend APIs.

  • clientId: cs-ui
  • Redirect URI: /auth/callback
  • PKCE: S256
Orders API

Order read/write, delivery status, address validation, replacement initiation.

  • clientId: cs-orders-api
  • Service Account enabled
  • Audience scopes supported
Workflow API

Orchestrates multi-step actions: policy check, tool execution, ticketing, replacement order flows.

  • clientId: cs-workflow-api
  • Service Account enabled
  • Client role: workflow

2️⃣ Identity, RBAC, and Service Accounts

Keycloak Realm Controls

The platform enforces least privilege via realm roles and group-based role assignments. Human users (support agents) can be granted order_read, order_write, ticket_write, while privileged actions like replacement_create are tightly controlled.

Capability Role Typical Principal
Read order details order_read Support agent / workflow
Update order order_write Support agent / workflow
Create replacement replacement_create Workflow service account
Open ticket ticket_write Support agent / workflow
Update address order_address_update Privileged support ops
Update status order_status_update Workflow / ops automation
Service-to-Service Identity

Backend services authenticate using Keycloak service accounts (client credentials), enabling controlled automation without embedding user passwords.

  • service-account-cs-orders-api
  • service-account-cs-workflow-api
  • JWT contains realm_access.roles for authorization decisions
  • Prefer short-lived access tokens; refresh only where needed

3️⃣ Network Boundaries and Secrets

Ingress and East-West Traffic

Place UI behind an edge proxy/WAF; restrict API ingress to private networks where possible. Enforce TLS everywhere (external + internal mTLS where feasible).

Secrets Management

Never store client secrets in Git. Load secrets from your vault / KMS / Kubernetes secrets.

  • Keycloak client secrets (for service accounts)
  • DB credentials
  • Signing keys handled by Keycloak (rotation policy)

4️⃣ Observability and Auditability

Structured Logs

JSON logs with correlation IDs, tenant, user, orderId, tool-call outcomes.

Metrics

Latency, error rates, tool success, policy denials, token failures.

Distributed Traces

Trace UI → Orders API → Workflow API → DB spans end-to-end.

Security Events

Auth failures, denied actions, suspicious retries, elevated privileges.

5️⃣ Deployment Readiness Checklist

Operational Rule: If the agent cannot prove (via logs + traces) that it respected policy + RBAC, the action is not production-safe.

Keycloak + OAuth2 / OIDC Architecture

Modern Identity, Token-Based Security, and Enterprise Federation with SAML 2.0

1️⃣ OpenID Connect (OIDC) Fundamentals

OpenID Connect (OIDC) is an identity layer built on top of OAuth2. It provides:

  • User Authentication
  • ID Tokens (JWT)
  • Access Tokens for APIs
  • Standardized Discovery & Metadata
In modern SaaS, OIDC replaces legacy session-based authentication with stateless, signed JWT tokens.

2️⃣ OAuth2 Grant Types Supported by Keycloak

Authorization Code + PKCE

Used for Web & SPA applications

  • Redirect to Keycloak login
  • PKCE challenge
  • Code → Token exchange
  • Secure against interception
Client Credentials

Service-to-Service communication

  • No user interaction
  • Machine identity
  • Scoped API access
Token Exchange

Delegation & Impersonation

  • Exchange user token
  • Obtain downstream client token
  • Ideal for API Gateways

3️⃣ JWT Token Anatomy

HEADER
{
  "alg": "RS256",
  "typ": "JWT"
}

PAYLOAD
{
  "sub": "alice",
  "iss": "https://keycloak.example.com",
  "aud": "orders-api",
  "realm_access": {
    "roles": ["user"]
  }
}

SIGNATURE
RS256 signed with realm private key

Resource Servers validate signature via JWKS endpoint.

4️⃣ Identity Federation via SAML 2.0

Keycloak can act as a SAML 2.0 Service Provider (SP) and federate identity from enterprise Identity Providers such as:

  • Okta (SAML 2.0 IdP)
  • Azure Entra ID (SAML 2.0 IdP)

In this model:

  1. User attempts login via OIDC Client App
  2. Keycloak redirects to external SAML IdP
  3. IdP authenticates user
  4. SAML Assertion returned to Keycloak
  5. Keycloak issues OIDC tokens (JWT)
This allows legacy enterprise SAML systems to integrate seamlessly into modern OAuth2 / OIDC ecosystems.

What is Generative AI?

Overview Concepts

Generative AI refers to AI systems that generate new content—text, images, code, audio, or structured data—based on patterns learned from training data. Most modern GenAI experiences are powered by foundation models (often large language models) that can be adapted via prompting, retrieval, or fine-tuning.

Input
Prompt, documents, tool results, conversation context
Model
LLM / multimodal model + safety + system instructions
Output
Answer, plan, code, tool calls, structured actions

Core GenAI Terms

Definitions

An LLM is a neural network trained to predict the next token (word piece) in a sequence. Despite that simple objective, it can perform reasoning-like behaviors, summarization, translation, coding, and more.

A foundation model is a broadly trained model (often on large, diverse datasets) that can be adapted to many tasks via prompting, retrieval augmentation, or fine-tuning.

Tokens are the units a model reads and produces (word pieces, punctuation, etc.). Pricing, context length, and latency often scale with token count.

The context window is the maximum amount of text (tokens) the model can consider at once—system instructions, conversation history, user prompt, and retrieved documents included.

Prompting is how you steer model behavior with instructions and context. Common layers: System (highest priority), Developer (app rules), User (task request).

RAG is a pattern where the system retrieves relevant documents (via search / embeddings) and feeds them into the prompt, grounding answers in your data and reducing hallucinations.

Embeddings are numeric vectors representing meaning. Vector search finds semantically similar content (e.g., “delivery issue” ↔ “package misdelivered”), enabling RAG.

Fine-tuning updates model weights on your curated examples to specialize behavior or style. Use it when prompting + RAG can’t reliably achieve required precision.

Tool calling lets the model request structured actions (API calls, DB reads, ticket creation). Your application validates permissions, applies policy, and executes the action safely.

An agent is a model-driven workflow that can plan steps, call tools, check results, and iterate. It’s not “magic”—it’s orchestration plus guardrails.

Risk & Guardrails

Hallucination
Model produces plausible but incorrect statements. Mitigate with RAG, citations, constrained decoding, and tool-based fact retrieval.
Prompt Injection
Malicious instructions in user content or retrieved docs. Mitigate with strict tool allowlists, sandboxing, and system-level rules.
Data Leakage
Sensitive data exposure via logs, context, or responses. Mitigate with redaction, least-privilege retrieval, and access controls.
Control What it does Example
Policy Engine Enforces business rules before executing actions “Overnight replacement only if SLA tier = Gold”
Tool Allowlist Restricts which tools can be called (and how) Read-only order lookup always allowed; refunds require approval
